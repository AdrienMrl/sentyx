teslcam REST API reference

Event-ingestion + read API served by internal/server. Reference generated from source; where it diverges from the narrative design doc, the code wins (differences flagged inline).

Base URL & auth

Base URL is deployment-specific, e.g. https://your-host:8090 (dev default 127.0.0.1:8090). No path prefix beyond the routes below.

When the server is started with a token, every endpoint except GET /healthz requires Authorization: Bearer <token>. A missing or wrong token returns 401 with a WWW-Authenticate: Bearer header. If no token is configured (local/trusted-network dev), auth is disabled entirely.

JSON request bodies are capped at 4 MiB and parsed with unknown fields rejected — an unexpected key yields 400 invalid JSON. Blob bodies are raw bytes and are not size-capped by the JSON limit.

Event lifecycle (v1)

  1. Upsert the logical event — PUT /v1/events/{event} (idempotent by key).
  2. Upload blobs content-addressed by SHA-256 — PUT /v1/blobs/{sha256} (idempotent, dedup).
  3. Publish a manifest generation listing typed artifacts — PUT /v1/events/{event}/manifests/{generation}.
  4. Finalize the generation once all blobs resolve — POST …/manifests/{generation}/finalize.
  5. Finalize atomically enqueues a durable analysis job; state walks receiving → ready → analyzing → done (or failed, retried up to 3×).

Design rationale (event identity, generations, settle timing, audit trail) lives in the Ingestion API design doc. This page is the field-level reference.

Ingestion (v1)

PUT /v1/events/{event} bearer Idempotently create or enrich a logical event ▶

Creates or updates the event keyed by the {event} path segment. The key may be any string without /, max 512 chars (the agent uses <device-id>:<source-directory-name>). Re-sending enriches metadata; trigger/location fields are only overwritten when non-empty.

Request body — EventUpsert (application/json)

FieldTypeReqDescription
device_idstringrequiredStable device identifier; must be non-empty.
sourceobjectrequiredSource descriptor (see below).
source.typestringrequiredMust equal "tesla_sentry".
source.directory_namestringrequiredTeslaCam source dir name, e.g. 2026-07-11_14-32-08.
detected_atRFC3339 timeoptionalWhen the agent first saw the event. Defaults to server time (UTC) if zero/omitted.
triggerobjectoptionalEnrichment from event.json; never a completion marker.
trigger.occurred_at_localstringoptionalLocal trigger timestamp (stored as event_ts).
trigger.camera_codestringoptionalTesla camera code.
trigger.reasonstringoptionalSentry trigger reason.
locationobjectoptionalEstimated location.
location.citystringoptionalCity name (stored on the event).
location.estimated_latitudenumberoptionalLatitude (kept in metadata_json only).
location.estimated_longitudenumberoptionalLongitude (kept in metadata_json only).

Example request

curl -X PUT https://host:8090/v1/events/pi-garage-01:2026-07-11_14-32-08 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "pi-garage-01",
    "source": { "type": "tesla_sentry", "directory_name": "2026-07-11_14-32-08" },
    "detected_at": "2026-07-11T18:32:10Z",
    "trigger": { "occurred_at_local": "2026-07-11T14:32:08", "camera_code": "5", "reason": "sentry_aware_object_detection" },
    "location": { "city": "Toronto", "estimated_latitude": 43.65, "estimated_longitude": -79.38 }
  }'

Example response — 200

{
  "id": "pi-garage-01:2026-07-11_14-32-08",
  "state": "receiving",
  "generation": 0
}

Responses

200Event upserted. Body: { id, state, generation } (generation = current finalized generation, 0 until first finalize).
400Invalid event key (empty, contains /, or >512 chars); missing device_id/source.directory_name; source.type ≠ tesla_sentry; or malformed/unknown-field JSON.
401Missing or invalid bearer token.
500Store failure.

PUT /v1/blobs/{sha256} bearer Store raw bytes under their verified content hash ▶

Body is the raw file bytes (any content type). {sha256} is 64 hex chars (upper/lower accepted, lowercased server-side). The server streams the body to a temp file while computing SHA-256, verifies it matches the path, then atomically moves it to data/blobs/<first2>/<sha256>. Idempotent: if the blob already exists (and Content-Length is unset or matches), the body is drained and status:"exists" is returned without rewriting.

Request

PartTypeReqDescription
{sha256}path paramrequired64 hexadecimal characters (SHA-256 of the body).
bodyraw bytesrequiredFile content. Content-Length is used for the idempotent short-circuit when the blob already exists.

Example request

curl -X PUT https://host:8090/v1/blobs/67d2a1... \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: video/mp4" \
  --data-binary @2026-07-11_14-32-00-front.mp4

Example response — 200 (stored)

{ "sha256": "67d2a1…", "size": 28123904, "status": "stored" }

Example response — 200 (already present)

{ "sha256": "67d2a1…", "size": 28123904, "status": "exists" }

Responses

200Stored or already present. Body: { sha256, size, status } with status "stored" or "exists".
400{sha256} is not 64 hex characters.
401Missing or invalid bearer token.
422Computed SHA-256 does not match the path (sha256 mismatch: received <got>). Bytes are discarded.
500Filesystem/store failure.
PUT /v1/events/{event}/manifests/{generation} bearer Declare the typed artifacts of one event generation ▶

Publishes (or replaces) the artifact set for a generation. {generation} is a positive integer and must equal the body's generation. Replacing an un-finalized generation's manifest overwrites its artifacts; a finalized generation is immutable. The response reports which referenced blobs are still missing (by hash, matched on hash and declared size).

Request body — Manifest (application/json)

FieldTypeReqDescription
generationintrequiredPositive; must match the URL segment.
observed_throughRFC3339 timeoptionalHigh-water mark of source observation. Defaults to server time if zero.
artifactsArtifact[]requiredTyped artifacts (see below). May be empty, but finalize needs ≥1 video.

Artifact object

FieldTypeReqDescription
idstringrequiredStable artifact id within the generation; non-empty.
kindstringrequiredNon-empty. Conventionally video | thumbnail | source_metadata | other (open string; only video is enforced at finalize).
sha256stringrequired64 hex chars; ties the artifact to a blob.
sizeint64requiredDeclared byte size; must be ≥0 and match the stored blob's size to resolve.
media_typestringoptionalMIME type. Stored but not validated. Note: the design doc implies this is required; the handler does not enforce it.
source_namestringrequiredOriginal filename; must be unique across the manifest's artifacts.
segmentobjectoptionalVideo segment info.
segment.started_at_localstringoptionalSegment start (local).
segment.camerastringoptionalOpen string camera name (e.g. front). Required by JSON shape when segment is present, but not otherwise validated.

Example request

curl -X PUT https://host:8090/v1/events/pi-garage-01:2026-07-11_14-32-08/manifests/1 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "generation": 1,
    "observed_through": "2026-07-11T18:34:20Z",
    "artifacts": [{
      "id": "2026-07-11_14-32-00-front.mp4",
      "kind": "video",
      "sha256": "67d2a1…",
      "size": 28123904,
      "media_type": "video/mp4",
      "source_name": "2026-07-11_14-32-00-front.mp4",
      "segment": { "started_at_local": "2026-07-11T14:32:00", "camera": "front" }
    }]
  }'

Example response — 200 (all blobs present)

{ "event_id": "pi-garage-01:2026-07-11_14-32-08", "generation": 1, "status": "verified" }

Example response — 200 (missing blobs)

{ "event_id": "pi-garage-01:2026-07-11_14-32-08", "generation": 1,
  "status": "incomplete", "missing_blobs": ["67d2a1…"] }

Responses

200ManifestStatus with status "verified" (all blobs resolved) or "incomplete" (+ missing_blobs[]). A missing blob is not an error here — only at finalize.
400Non-positive/non-integer generation; body generation ≠ URL; artifact validation failure (missing id/kind/source_name, bad sha256, negative size, duplicate source_name); malformed/unknown-field JSON.
401Missing or invalid bearer token.
404Event does not exist (upsert it first).
409The target generation is already finalized (immutable).
POST /v1/events/{event}/manifests/{generation}/finalize bearer Verify a generation and make it analysis-ready ▶

Seals a generation. Succeeds only if the manifest exists, contains at least one video artifact, and every artifact resolves to a stored blob of the declared size. On success the manifest is marked finalized, artifacts are materialized into the file view, the event moves to state:"ready" with current_generation updated, and a durable analysis job is enqueued — all in one transaction. The request body is optional.

Request body — FinalizeRequest (optional, application/json)

FieldTypeReqDescription
completion_reasonstringoptionalFree-text reason (e.g. post_trigger_window_settled). Accepted, not used for logic.
settled_atRFC3339 timeoptionalWhen the agent decided the event settled. Accepted, not used for logic.

An empty body (Content-Length 0) is valid; a present body is decoded with unknown fields rejected.

Example request

curl -X POST https://host:8090/v1/events/pi-garage-01:2026-07-11_14-32-08/manifests/1/finalize \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{ "completion_reason": "post_trigger_window_settled", "settled_at": "2026-07-11T18:34:32Z" }'

Example response — 200 (ready)

{ "event_id": "pi-garage-01:2026-07-11_14-32-08", "generation": 1, "status": "ready" }

Example response — 409 (blobs still missing)

{ "event_id": "pi-garage-01:2026-07-11_14-32-08", "generation": 1,
  "status": "incomplete", "missing_blobs": ["67d2a1…"] }
Discrepancy vs task/doc: incomplete finalize (missing blobs) returns 409 Conflict, not 422. The only 422 on this endpoint is a manifest with no video artifact (errNoVideoArtifact) — a rule the narrative doc does not mention.

Responses

200Finalized. ManifestStatus with status "ready". Analysis job enqueued.
400Non-positive/non-integer generation, or malformed/unknown-field JSON body.
401Missing or invalid bearer token.
404Event not found, or no manifest for that generation.
409Generation older than the event's current generation (errOldGeneration), or blobs still missing — body carries status:"incomplete" + missing_blobs[].
422Manifest contains no video-kind artifact.
500Store/transaction failure.

Usage

GET /usage bearer Aggregate analysis token spend per model ▶

Sums recorded token usage across all analyzed events, grouped by model, for cost accounting (multiply by the model's per-token price).

Notes — where code and the narrative doc diverge (code wins):
  • Incomplete finalize (referenced blobs missing) returns 409 Conflict with status:"incomplete" + missing_blobs, not 422.
  • Finalize additionally requires at least one video-kind artifact (else 422) — the doc does not state this.
  • Artifact media_type is not validated as required, though the doc treats it as part of every artifact.
  • Blob upload returns a status field ("stored" / "exists") not shown in the doc's examples.
  • Old-generation rejection (409) is enforced only at finalize; PUT manifest checks immutability of a finalized generation (409) but not ordering.
